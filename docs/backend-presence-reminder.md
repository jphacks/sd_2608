## 在席と連続性

- 開始後は有効な顔サンプルを5件集め、直近5件中3件以上が顔あり、かつ最新も顔ありで present。再送・snapshot 読取り・PC の更新では票を増やさない。
- 顔が見えていれば、入力が止まっていても在席を維持する。短い顔欠落は uncertain とし、連続区間と時間を維持する。
- 顔なし30秒＋入力停止30秒で away。区間の終了時刻を最初の顔なしへ戻し、離席確定時刻とは分けて保持する。離席確定イベントは1回だけ。入力だけでは帰席とせず、安定した顔ありで新セッションを開始する。
- 顔なし30秒でも入力が続いていれば、離席予約を出さず、その確定時点で interrupted として区間を閉じる。後から入力停止条件がそろっても、この中断済み区間から離席レポート要求を出さない。
- センサーの取得不可・保護画面・5秒超の古い入力は unknown。連続性と通知を失効させ、復帰後は顔の票を集め直す。更新間隔が5秒超開いた場合は、中断中の時間を足さず直前の更新時点で区間を閉じる。
- 比較には Rust の単調時計を使う。UTC の補正で30分・60分の期限を進めない。終了日時は開始日時と単調時計の経過から導く。表示用の進行中 elapsedMs は秒単位にそろえる。

## 区切りと通知

| ルール | 通常 | demo |
|---|---|---|
| 顔なし・入力停止・連続性中断 | 30秒 | 5秒 |
| 最初の通知が可能／区切り待ち上限 | 30分／35分 | 30秒／35秒 |
| No 後の抑制／最大延期 | 2分／10分 | 2秒／10秒 |
| 区切りを待たない上限 | 60分 | 60秒 |
| 上限後の No／Yes の猶予 | 5分／10分 | 5秒／10秒 |
| 入力停止による区切り | 5秒 | 2秒 |
| 外部ウィンドウ切替後の期間／入力停止 | 10秒以内／2秒 | 5秒以内／1秒 |

区切りには固有の ID を付け、同じ入力停止から1回だけ発行する。タイトルの変更は切替に数えず、PID とウィンドウ ID を使う。ペット・除外対象は区切り対象外とし、対象外から戻っただけで古い入力停止を再利用しない。これらは保護画面と区別し、顔・入力停止情報が有効なら在席自体は維持する。

通知は present のときだけ表示する。uncertain では隠し、短い欠落から戻る場合は同じ通知 ID を使う。離席・中断・停止・回答で失効する。60分到達時に通常通知が表示中なら、ID と shownAt を維持して hard に更新する。60分未満の No／Yes の猶予は最初の60分到達で打ち切り、60分以降に回答した No／Yes は、それぞれ5分／10分の猶予を守る。

AppController は away → uncertain → present という帰席の安定化を経ても、一度だけ「おかえりなさい」を出すようにした。unknown・停止・別 runtime を経た場合は帰席として扱わない。

## 回答とレポートの境界

`reminder_respond` は回答直前にも入力の鮮度と状態を評価し、現在表示できる trackingId・sessionId・reminderId を照合する。隠れた通知、回答済み通知、旧セッションの回答は拒否する。同じ requestId・内容なら以前の結果を返し、別内容での再利用は validation。

**B-04 の Yes は回答受付まで。** Yes と自然離席から Domain の `ReportRequested` を発行し、同じセッションでは重複発行しない。Yes でも連続在席をリセットしない。No・観測不能・顔なし中の操作継続による中断・Stop からはレポート要求を出さない。

現在のイベント処理は未接続の案内を出すだけで、履歴固定・予約・ジョブ・カードを作らない。Yes の応答は `reportId:null` となり、「生成は未接続」「カードは作成していない」と画面に表示する。イベントの保存・再生も未実装。**B-05／06 は同じ状態更新内の `handle_events` に保存・予約を接続する。** 将来のジョブ ID と Domain の要求済みフラグは別の情報として扱う。
