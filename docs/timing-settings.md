# 時間の設定

設定画面で通常版とデモ版の時間を別々に編集・保存できます。記録を停止して保存し、次の記録開始から選択した版の設定を適用します。各版の「時間を初期値に戻す」はその版の入力だけを戻し、「設定を保存」で確定します。

`SettingsInput/View.timings` に `{ normal: TimingSettings, demo: TimingSettings }` を保存します。各フィールドは整数ミリ秒で、入力は1秒単位、最大24時間です。通常版の長い時間は分、短い時間とデモ版は秒で入力します。分の小数も使えます。以下はすべて従来の初期値です。

| フィールド | 内容 | 通常版 | デモ版 |
| --- | --- | --- | --- |
| `firstMs` | 休憩の目安（区切りで初回通知） | 30分 | 30秒 |
| `advanceNoticeLeadMs` | 休憩目安の何分・何秒前に予告するか | 3分 | 3秒 |
| `firstLimitMs` | 区切りがなくても初回通知する連続在席時間 | 35分 | 35秒 |
| `cooldownMs` | 「今は続ける」後の通知抑制 | 2分 | 2秒 |
| `snoozeMs` | 「今は続ける」後の再通知上限 | 10分 | 10秒 |
| `hardMs` | 強調通知を始める連続在席時間 | 60分 | 60秒 |
| `hardRepeatMs` | 強調通知を断った後の再通知間隔 | 5分 | 5秒 |
| `yesGraceMs` | 「レポートを作る」後の次の通知までの猶予 | 10分 | 10秒 |
| `absenceMs` | 顔なし・PC無操作で離席を確定するまで | 30秒 | 5秒 |
| `reportDelayMs` | 離席確定からレポート作成まで | 5分 | 5秒 |
| `idleMs` | 作業の区切りとする無操作時間 | 5秒 | 2秒 |
| `switchWindowMs` | ウィンドウ切り替え後の区切り判定期間 | 10秒 | 5秒 |
| `switchIdleMs` | 切り替え後に区切りとする無操作時間 | 2秒 | 1秒 |

`advanceNoticeLeadMs`、`reportDelayMs`、`cooldownMs`、`yesGraceMs` は0秒にできます。0秒の予告は無効、離席後の待ち時間は即時作成です。他の項目は1秒以上が必要です。休憩目安≦初回上限≦強調開始、予告時間≦休憩目安、通知抑制≦再通知上限、切り替え後無操作≦切り替え判定期間の関係をフロントとRustの保存時に検証します。

保存スキーマは1を維持します。旧 `settings.json` の `timings` 欠落は通常版・デモ版それぞれの従来値として復元します。新しいIPCスナップショットでは両版の全フィールドが必須です。正本の初期値はRustの `domain::timings::Timings::{NORMAL,DEMO}` で、共通JSON fixtureとテストでTypeScriptの初期値との一致を確認します。

顔の観測周期・センサー入力の鮮度・通信タイムアウト・データ保持期間・描画アニメーションの長さは内部処理の値として従来どおりです。モックでは確定した在席状態を直接入力するため離席確定までの待機や区切りのセンサー判定は模擬しませんが、通知・レポートの予定時間には同じ設定を使います。
