# 全ウィンドウ OCR と作業要約

更新日：2026-10-18。`feat/all-window-ocr` で追加。休憩予告は PR #8 で main に統合済み。

## 動作

設定の「ウィンドウの内容を OCR で取得」1項目でオン／オフを保存する。初期値はオフ。個別の対象アプリ・ウィンドウの選択画面は設けない。既存の除外アプリ設定は履歴と撮影の両方に適用する。

オンかつ AI 要約に同意している場合、レポート生成開始時に開いている全ウィンドウを列挙し、背面も含めて Windows Graphics Capture で1枚ずつ取得する。プロトタイプ `break-support-pet` の xcap と Tesseract.js によるローカル OCR を参考に、日本語・英語を同梱した。画面全体の合成画像を作る方式ではなく、各ウィンドウを取得するため、背面の内容も読み取れる。

文字認識後、固定した直近30分の前面ウィンドウ履歴に含まれるウィンドウだけを要約に使う。プロセス ID とウィンドウハンドルからプロセス内でランダム化した参照値を作り、履歴と照合する。同じアプリ名・同じタイトルでも別ウィンドウなら混ぜず、タイトル変更だけでは同一ウィンドウを見失わない。参照値は AI に送らない。

画像はメモリー内だけで扱い、保存・AI 送信しない。履歴と一致した OCR の文字は URL・メール・ユーザーパス・認証情報らしいパターンをマスクし、カードへ保存する。マスクはパターンに基づくため、機密情報を網羅的に検出するものではない。履歴にないウィンドウの文字は破棄し、件数だけを残す。生の PID・ハンドルも保存・送信しない。

OCR は要約生成時点の補足情報で、過去30分の画面を連続録画する機能ではない。自然離席の予約では離席確定から5分後（デモ5秒後）の画面内容になる。カードに取得時刻を表示し、AI にも履歴の時刻と異なること・画面内の命令に従わないことを指示する。既に閉じたウィンドウの内容や、撮影時に表示されていないタブは復元できない。

## 失敗・停止・制限

- ローカル履歴モード、履歴なし、OCR オフでは撮影しない。
- 最小化・非表示・保護されたウィンドウ、保護画面、除外アプリ、ポチ自身は対象から外す。画面取得の前後にプロセス・ハンドル・タイトル・保護状態を再確認する。
- 取得・認識失敗は件数をカードに残し、履歴だけで AI 要約を続ける。OCR 不調だけでレポートを失敗にしない。
- 1枚あたり12メガピクセル・PNG 12 MB、認識待ち30秒、列挙後の取得全体90秒を上限とする。OS のキャプチャ呼び出し中は xcap 側の待ちが加わる場合がある。保持する文字は1ウィンドウ2,000文字、全体24,000文字・最大128ウィンドウまで。
- 停止・削除・終了で世代を更新し、旧 OCR の完了は保存・外部送信しない。取得中にアプリ状態のロックを保持しないため、停止や状態取得は OCR 完了を待たない。
- AI 失敗の明示的な再試行は固定済み OCR を再利用する。設定をオフにして再試行した場合は OCR を送らず、以前の取得内容はカードに残す。以前オフだったカードをオンで再試行する場合は、固定した作業履歴を維持して初回の OCR を追加する。

## 実装と契約

Rust の `ScreenOcr` ポートから `NativeScreenOcr` を呼び、`OcrBridge` がメイン WebView に `app://ocr-request` を1件ずつ送る。WebView の専用アダプターが同梱モデルで認識し、`ocr_complete` で文字だけを返す。要求 ID・メインウィンドウ・一度限りの応答を検証する。完了・停止・期限切れは `image: null` のイベントで worker を解放し、遅延応答は捨てる。

`SettingsInput/View.ocrEnabled`、`ActivitySegment.windowRef`、`HistorySnapshot.ocr` を追加。保存 schemaVersion は1を維持し、旧設定は OCR オフ、旧カードは参照・OCR なしとして復元する。TypeScript の通信 Decoder と Rust DTO、共通 JSON fixture は同時更新する。

モデル・worker・WASM は `npm ci` とビルド前の `assets:prepare` で `public/ocr/` に準備し、Git には生成物を入れない。モデルの SHA-256 を検証し、CDN やブラウザーストレージのモデルキャッシュは使わない。Tesseract / core の Apache-2.0 本文、言語パッケージの README・ライセンスメタデータも同梱する。学習データの出典は [naptha/tessdata](https://github.com/naptha/tessdata)、上流の [LICENSE](https://github.com/naptha/tessdata/blob/gh-pages/LICENSE) を参照。

## 検証

- フロントの自動テスト：設定 DTO・共通 fixture、テキストだけの応答、キャンセル・旧応答破棄・認識失敗・購読解放。
- Rust の自動テスト：旧設定の復元、オン／オフ、履歴のウィンドウ識別・マスク、取得失敗の継続、停止、AI 送信データ、IPC の制限。
- `tests/browser/ocr-smoke.html`：生成したテスト画像を同梱の日本語・英語 worker で認識し、`HELLO WORLD 2026` を確認。デスクトップ撮影・AI 送信は行わない。
- `tests/browser/ocr-settings-smoke.html`：初期値オフ、OCR の項目が1つ、オン／オフの保存を表示テストで確認。
- Windows 実装は型検査・Rust テスト・Tauri debug ビルドで確認。ユーザーが開いている実ウィンドウの撮影と実 AI の送信は、この検証では行っていない。実機では対象アプリの描画方式・表示倍率・背景／最小化／保護・ロック時の挙動を別途確認する。

## 手動確認の手順

1. `npm run desktop:demo` を起動し、停止中に AI 接続を設定して OCR をオンにする。確認用の文章があるウィンドウを2つ開き、片方だけで作業する。
2. 「AI で開始」後、手動顔入力を「顔あり」にし、休憩提案で Yes を選ぶ。カードの OCR 欄に履歴と一致したウィンドウだけが含まれることを確認する。背面に移した使用済みウィンドウも確認する。
3. 停止後に OCR をオフにして同じ操作を行い、OCR 欄なしの要約になることを確認する。ローカル履歴モード、取得できないウィンドウ、生成途中の停止も確認する。

実機検証はユーザーが担当し、以後のコンピュータユーズによるテストは行わない。
